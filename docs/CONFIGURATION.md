# Configuration Reference (`CONFIGURATION.md`)

**Version:** `0.1.0`  

---

## 1. Overview

The **AI Engineering Framework** separates configuration into three scopes:
1. **Project Configuration (`project.framework.json`):** Checked into the root of a consumer repository (Tier 3). Controls workflow profile, active platform adapters, quality gates, and enabled optional skill packs.
2. **Local Developer Overrides (`project.framework.local.json`):** Git-ignored per-developer overrides (e.g., preferred communication voice like `caveman` or local tool paths).
3. **Platform Adapter Configurations:** Generated/synced files in `.github/`, `.agents/`, `.claude/`, `.codex/`, and `.gemini/` (Tier 2).

---

## 2. `project.framework.json` Schema & Options

Below is a complete annotated example of `project.framework.json` (template at [`templates/project.framework.json`](../templates/project.framework.json), validated by [`core/schemas/framework-config.schema.json`](../core/schemas/framework-config.schema.json)):

```json
{
  "$schema": "./core/schemas/framework-config.schema.json",
  "frameworkVersion": "0.1.0",
  "projectName": "my-software-project",
  "workflowProfile": "standard",
  "enabledPlatforms": [
    "antigravity",
    "copilot",
    "claude-code",
    "codex",
    "gemini-cli"
  ],
  "optionalSkillPacks": {
    "communication": ["caveman"],
    "frontendDesign": [],
    "growthMedia": []
  },
  "qualityGates": {
    "requireTddRedGreen": true,
    "requireIndependentCodeReview": true,
    "requireGraphifyCheck": true,
    "minimumTestCoveragePercent": 80
  },
  "security": {
    "enforcePreCommitSecretScan": true,
    "allowActiveSecurityTesting": false,
    "strixProfilePath": "security/strix-profile.yaml"
  },
  "paths": {
    "specsDir": "docs/specs",
    "adrDir": "docs/adr",
    "plansDir": "docs/plans",
    "retrospectivesDir": "docs/retrospectives",
    "stateDir": ".framework-state"
  }
}
```

### 2.1 Configuration Fields Reference

| Field | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `frameworkVersion` | `string` | `"0.1.0"` | SemVer version of the installed AI Engineering Framework |
| `projectName` | `string` | Repository folder name | Identifier used in handoff manifests and reports |
| `workflowProfile` | `"full"` \| `"standard"` \| `"hotfix"` | `"standard"` | Controls ceremony depth in `docs/WORKFLOW.md` |
| `enabledPlatforms` | `string[]` | All 5 platforms | Platforms generated by `scripts/sync_adapters.py` and `scripts/bootstrap.py` |
| `optionalSkillPacks.communication` | `string[]` | `["caveman"]` | Optional communication style skills (`caveman`) |
| `optionalSkillPacks.frontendDesign` | `string[]` | `[]` | Enable `["web-design-guidelines", "canvas-design"]` for UI/frontend projects |
| `optionalSkillPacks.growthMedia` | `string[]` | `[]` | Enable `["seo-audit", "ai-seo", "video-lens", "video-use", "content-strategy", "pricing"]` only for marketing/docs/growth workflows |
| `qualityGates.requireTddRedGreen` | `boolean` | `true` | Requires failing test creation before implementation in Phase 9 |
| `qualityGates.requireIndependentCodeReview` | `boolean` | `true` | Requires Phase 10 review before Phase 13 release |
| `qualityGates.requireGraphifyCheck` | `boolean` | `true` | Uses `graphify` knowledge graph during architecture and review phases when installed |
| `security.allowActiveSecurityTesting` | `boolean` | `false` | Must remain `false` unless explicit human approval (`Gate-Sec`) and target scope are configured |

## 3. Configuring Platform Adapters

Platform adapters are configured from canonical sources via `scripts/sync_adapters.py`:

| Platform | Generated / Managed Config Files | Customization Mechanism |
| :--- | :--- | :--- |
| **GitHub Copilot** | `.github/copilot-instructions.md`, `.github/instructions/framework.instructions.md`, `.github/prompts/*.prompt.md`, `.github/agents/*.agent.md` | Add project-specific stack rules in `.github/instructions/<stack>.instructions.md` |
| **Google Antigravity** | `GEMINI.md`, `AGENTS.md`, `.agents/rules/framework-core.md`, `.agents/skills/`, `adapters/antigravity/hooks.json` | Add workspace rules in `.agents/rules/project-*.md` |
| **Claude Code** | `CLAUDE.md`, `.claude/agents/*.md`, `.claude/commands/*.md`, `adapters/claude-code/settings.json` | Put machine-local overrides in `.claude/settings.local.json` (git-ignored) |
| **OpenAI Codex** | `AGENTS.md`, `adapters/codex/config.toml`, `.agents/skills/` | Put machine-local overrides in `.codex/config.local.toml` (git-ignored) |
| **Gemini CLI** | `GEMINI.md`, `.gemini/commands/*.toml`, `adapters/gemini-cli/settings.json` | Put machine-local overrides in `.gemini/settings.local.json` (git-ignored) |

## 4. Environment Variables & Secrets Policy

1. **Zero Secrets in Git:** Never place API keys, OAuth tokens, database connection strings, or private URLs in `project.framework.json`, `mcp_config.json`, or any tracked file.
2. **Variable Placeholders:** In MCP configurations (`integrations/mcp/mcp.template.json`), always reference secrets via placeholders (`${GITHUB_PERSONAL_ACCESS_TOKEN}`, `${STRIX_LLM_API_KEY}`) and declare them in `.env.example` without values.
